## Linked into `ua_host`, not vendored (video, `runtime/media`)

The media core links these decoders statically, from the build images' Debian / Ubuntu packages
(`runtime/media/docker/`); none of their source is in this repository. `runtime/media/build.sh`
copies each package's copyright file into `runtime/media/out/[arm64/]licenses/`: distribute those
with a `ua_host` built this way.

| what | version (armhf: Debian 12; arm64: Ubuntu 20.04) | licence | used for |
|---|---|---|---|
| [libvpx](https://chromium.googlesource.com/webm/libvpx) (`libvpx-dev`) | 1.12.0 / 1.8.2 | BSD-3-Clause (+ WebM project patent grant) | VP8 / VP9 decoding |
| [libvorbis](https://xiph.org/vorbis/) + [libogg](https://xiph.org/ogg/) (`libvorbis-dev`, `libogg-dev`) | 1.3.7 + 1.3.5 / 1.3.6 + 1.3.4 | BSD-3-Clause | Vorbis decoding |
| [libopus](https://opus-codec.org/) (`libopus-dev`) | 1.3.1 | BSD-3-Clause | Opus decoding |
| [OpenH264](https://github.com/cisco/openh264) (armhf: `libopenh264-dev`; arm64: Debian 12's source package built in the image) | 2.3.1 | BSD-2-Clause | H.264 decoding. Built from source, it carries no MPEG LA patent licence (Cisco's own binaries do); whether that matters is the distributor's call |

The tests also use the encoders of the same packages (libvpx, libvorbisenc, libopus, OpenH264) to
make their clips, and `runtime/media/build.sh test-ffmpeg` runs Debian's FFmpeg in a test image
(test patterns only; nothing of it is kept).

(`dlopen`, no Mono headers). Distribute the built libraries with these notices (each is in the
fetched source tree, `<work>/src/<branch>/`):

| what | fetched from | licence | built into |

## Used at run time when the system has it (not shipped)

The system's [FFmpeg](https://ffmpeg.org/) `libavcodec` (LGPL 2.1+, or GPL depending on the
firmware's build), opened with `dlopen` by `runtime/media/um_ffmpeg.c` when present: AAC, MP3,
HEVC and some H.264. Nothing of FFmpeg is linked, compiled in or distributed.

The system's [libcurl](https://curl.se/) (curl licence, MIT-style), opened with `dlopen` by
`runtime/jni/up_http.c` only when `UA_HTTP=1` (Unity 2017.4 - 2018.4 web requests). The system's CA
bundle is read as data (runtime/jni/up_tls.c). Native plugins a port supplies (e.g. FMOD's or
Wwise's libraries, docs/plugins.md) come under their own licences and are never part of this
repository. The TLS tests (`runtime/jni/test/tls_test.sh`) run Debian's mbedTLS (Apache 2.0),
OpenSSL (Apache 2.0), Python and libcurl in a test image; nothing of them is kept.

## Not included

- Unity's Android player (`libunity.so`, `libmain.so`, `libmono.so`, the managed `UnityEngine*.dll`,
  `unity default resources`): proprietary, from Unity's editor installers, under Unity's terms. You
  unpack it yourself; this repository only reads it. The same for Unity's class libraries
  (`mscorlib.dll`, `System*.dll`, facades) that `pmunity winbcl` reads from Unity's Windows editor
  installer for a build (a port's setup reads them on the handheld).
- Any game's files. The converter works on your own copy.

## Used at build or conversion time (not vendored)

Debian's armhf cross toolchains and libraries (Dockerfiles), SDL2, Mesa (test rig), Python
packages in `convert/requirements.txt` (UnityPy MIT, lz4 BSD, astc-encoder Apache 2.0, Pillow
MIT-CMU, texture2ddecoder MIT, pyelftools public domain).

[Mono.Cecil](https://github.com/jbevain/cecil) 0.11.6 (MIT, Copyright (c) 2008 - 2015 Jb Evain,
Copyright (c) 2008 - 2011 Novell, Inc.), a NuGet package `tools/asmpatch` is built with:
`out/linux-arm64/asmpatch` contains it and the .NET runtime (MIT; distribute that binary with
Mono.Cecil's licence and the runtime pack's `LICENSE.TXT` and `THIRD-PARTY-NOTICES.TXT`).

[HLSLcc](https://github.com/Unity-Technologies/HLSLcc) (MIT; it includes bstrlib, BSD), fetched by
`tools/hlslcc/build.sh` at a pinned commit and compiled into `pmhlslcc` (Direct3D 11 shaders,
`pmunity shaders --from d3d11`): distribute that binary with `pmhlslcc.LICENSE.txt`, which the
build writes next to it. A port that translates Direct3D 11 shaders ships the aarch64 build
(`ARCH=arm64 tools/hlslcc/build.sh`: GCC's libstdc++ and libgcc linked in, under the GCC Runtime
Library Exception) as `setup/pmhlslcc`, with that licence as `licenses/LICENSE.pmhlslcc-HLSLcc.txt`.

[SPIRV-Cross](https://github.com/KhronosGroup/SPIRV-Cross) (Apache 2.0; its headers `spirv.hpp` and
`GLSL.std.450.h` MIT, The Khronos Group) and [SMOL-V](https://github.com/aras-p/smol-v) (MIT or
public domain, Aras Pranckevicius), fetched by `tools/spirvcross/build.sh` at pinned commits and
compiled into `pmspirvcross` (Vulkan shaders, `pmunity shaders --from vulkan`): distribute that
binary with `pmspirvcross.LICENSE.txt` (both licences, Apache 2.0's text included), which the build
writes next to it. A port that translates Vulkan shaders ships the aarch64 build (`ARCH=arm64
tools/spirvcross/build.sh`: GCC's libstdc++ and libgcc linked in, under the GCC Runtime Library
Exception) as `setup/pmspirvcross`, with that licence as
`licenses/LICENSE.pmspirvcross-SPIRV-Cross-SMOL-V.txt`. The Metal path (`--from metal`) is the
converter's own Python (`convert/pmunity/shaders/metal.py`); nothing third-party.

## Shipped in a port's release zip (`pmunity port package`)

Besides `ua_host` (above) and asmpatch when the port uses it (above, with the .NET runtime's and
Mono.Cecil's licences), a port made with `pmunity port new` carries the setup's Python,
`tools/port/build_pybundle.sh`'s bundle: [python-build-standalone](https://github.com/astral-sh/python-build-standalone)'s
CPython 3.12 (PSF licence) with UnityPy (MIT), lz4 (BSD), astc-encoder-py (MIT; ARM's
astc-encoder inside it: Apache 2.0), Pillow (MIT-CMU), texture2ddecoder (MIT), etcpak (MIT),
brotli (MIT), archspec (Apache 2.0 or MIT), attrs (MIT), fsspec (BSD-3-Clause), tpk_ar (MIT) and
pyfmodex (MIT), downloaded from their releases and PyPI when the bundle is built (none of it is in
this repository), and this repository's own guided_astc extension (`convert/native/guided_astc`,
built from its source in the same container). The packager collects each one's licence
text from the bundle into the zip's `licenses/LICENSE.setup-python.txt`; the setup removes the
bundle from the handheld when it is done.

## The box64 route (`tools/box64`): built from source, not vendored

`tools/box64/build.sh` clones these at a release tag and builds them in Docker; none of their
source or binaries is in this repository. A port that ships the binaries ships the licence files
the build writes to `tools/box64/out/licenses/`.

| what | version | licence | used for |
|---|---|---|---|
| [box64](https://github.com/ptitSeb/box64) | v0.4.4 | MIT | x86_64 -> ARM64 translation of a game's Linux build |
| box64's `x64lib/libstdc++.so.6`, `libgcc_s.so.1` (x86_64 GCC runtime, as box64 ships them) | from box64 v0.4.4 | GPL-3.0 with the GCC Runtime Library Exception 3.1 | the x86_64 C++ runtime Unity's players link |
| [gl4es](https://github.com/ptitSeb/gl4es) | v1.1.6 | MIT | OpenGL 2.1 on GLES 2 for Unity's legacy OpenGL 2 renderer |
