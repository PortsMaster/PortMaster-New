## 一、安装

1. 把压缩包里的 `Wiliwili.sh` 和 `wiliwili` 文件夹解压到 ROCKNIX 的端口目录：

   ```
   /storage/roms/ports/Wiliwili.sh
   /storage/roms/ports/wiliwili/...
   ```

   （`/storage/roms` 就是 `/roms`，两者是同一个目录。）

2. 在 EmulationStation 里进入 **Ports** 分类，选择 **wiliwili** 启动。
   首次启动前请先连好 Wi-Fi。

3. 第一次进入需要在应用里登录 B 站账号（扫码或账号密码）。登录信息、设置、
   缓存都会保存在 `wiliwili/conf/` 里，升级端口时保留这个目录即可。

4. 退出：手柄 **Select + Start**（PortMaster 的通用退出热键），
   或按设备自身的退出组合键。

## 二、界面分辨率：480P

界面按 **640×480（480P）** 的画布排版，再缩放到实际屏幕。这样做的好处：

* 640×480（1 倍）屏幕上 **1:1 像素对齐**，文字和图标最锐利；
* 任何 480P 的**整数倍**屏幕都能精确整数缩放，不会出现半像素糊边——
  1280×960（2 倍）、1920×1440（3 倍）等。

### 为什么需要改动

上游 wiliwili 的界面缩放只有 **544p / 720p / 900p / 1080p** 四档
（`APP_UI_SCALE` → 960×544 / 1280×720 / 1600×900 / 1920×1080），
**没有 480P**，直接写 `"480p"` 会掉进默认分支变成 1280×720（界面更小、更不清晰）。

因此本移植对程序做了一处**极小的定点修改**，把第一档 `544p` 换成真正的 `480p`：
只改动了 4 个位置、共 8 个字节——

| 位置 | 原内容 | 改后 | 作用 |
|---|---|---|---|
| `.text` `0x37fb1d` | `movz w3, #960` | `movz w3, #640` | 画布宽度 |
| `.text` `0x37fb21` | `movz w2, #544` | `movz w2, #480` | 画布高度 |
| `.rodata` `0x7c58b8` | `"544p"` | `"480p"` | 选项值/比较用字符串 |
| `.rodata` `0x7b951a` | `"544p"` | `"480p"` | 设置项文案的 i18n 键 |

同时把 7 种语言的 `setting/app/others/scale/544p` 文案键改名为 `480p`
（文案改为「适合小屏幕 (640x480)」等）。除此之外程序**没有任何其他改动**，
其余三档（720p/900p/1080p）行为完全不变。

> 如果想要原版行为：把 `wiliwili/conf/wiliwili/wiliwili_config.json` 里的
> `app_ui_scale` 改成 `720p`/`900p`/`1080p` 即可，无需还原二进制。

## 三、动态库

程序本体需要的 `libmpv.so.2` 及其**全部依赖**（约 194 个 .so，取自 Ubuntu 24.04 arm64）
放在 `libs.aarch64/`，端口自带完整、版本自洽的播放栈（mpv + FFmpeg 6 系列）。
这样就不依赖设备上是否附带对应版本的 FFmpeg。

**故意不打包**下面这些库，改用 ROCKNIX 系统自带的版本：

| 类别 | 库 | 原因 |
|---|---|---|
| glibc / C++ 运行时 | `libc` `libm` `libdl` `librt` `libpthread` `libstdc++` `libgcc_s` | 必须与内核/驱动匹配 |
| 图形驱动 | `libEGL` `libGL` `libGLESv2` `libgbm` `libdrm` `libmali` | 必须用设备上的驱动 |
| **显示与合成器** | `libwayland-client` `libwayland-cursor` `libwayland-egl` `libxkbcommon` | SDL2 通过 dlopen 加载它们，混用不同来源会导致创建窗口失败 |
| 音频 / 会话 | `libasound` `libpulse` `libdbus-1` | 需要和设备上的守护进程通信 |
| 其他 | `libSDL2-2.0.so.0` `libudev` `libsystemd` `libssl.so.3` `libcrypto.so.3` | 系统版本更合适 |

上面这些库是 ROCKNIX 自带 SDL2 包的硬依赖，所以设备上一定有。

已验证：

* 程序需要的 22 个 `mpv_*` 符号，打包的 `libmpv.so.2` 全都导出；
* 打包库要求的最高 glibc 符号版本是 **GLIBC_2.38**（ROCKNIX 的 glibc ≥ 2.40）；
* 遍历全部 194 个库的 `DT_NEEDED`：除上表列出的系统库外全部在包内自解析。

## 四、显示与手柄

* **显示**：ROCKNIX 在 `/etc/profile.d/050-sway.conf` 里设定
  `SDL_VIDEODRIVER=wayland`、`WAYLAND_DISPLAY=wayland-1`、
  `XDG_RUNTIME_DIR=/var/run/0-runtime-dir`。启动脚本会把这些值补全（即使端口不是
  从 EmulationStation 启动也不会缺），并给窗口设置固定的 Wayland app-id，
  以便 ROCKNIX 的 `portmaster_sway_fullscreen.sh` 能把窗口全屏。
* **驱动回退**：脚本按 `wayland → kmsdrm → offscreen` 顺序尝试；某个驱动如果在
  20 秒内就异常退出，就认为它创建窗口失败，自动换下一个。
* **手动指定驱动**：新建文件 `wiliwili/conf/videodriver`，内容写
  `wayland` 或 `kmsdrm` 即可强制使用（删除该文件则恢复自动）。
* **手柄**：wiliwili 自己通过 SDL2 读手柄，所以 `gptokeyb` 不加载按键映射文件，
  只负责提供退出热键。若设备把按键暴露成键盘设备而识别不到手柄，可自行给
  `$GPTOKEYB` 加上 `-c` 映射文件。

## 五、排错

所有输出都会写到 `wiliwili/log.txt`，里面有：环境变量、glibc 版本、
`/dev/dri` 设备、Wayland socket、每个驱动尝试的结果。

* **黑屏跳出**：先看 `wiliwili/log.txt`。脚本会在第二次 wayland 尝试时打开
  `WAYLAND_DEBUG=1`，把 Wayland 协议层日志存到 `wiliwili/log-wayland-trace.txt`，
  并在 `log.txt` 里贴出**开头 40 行**和**结尾 40 行**，创建窗口失败的原因就在里面。
* **更详细的应用日志**：手动执行
  `./wiliwili.aarch64 -d -t -o app.log`（`-d` 调试日志，`-t` mpv 输出）。
* 确认卡上剩余空间（缓存和临时文件需要约 250 MB）。
* 网络相关报错：确认已联网，且系统时间正确（B 站接口对时间敏感）。

## 六、更新端口

同一个端口目录下执行随包的 `update.sh`（`sh update.sh`）即可完成增量更新，
它会替换启动脚本并清理不应由端口提供的系统库。
